> **目标**：把七张明选卡片（spec §13.5）的依赖系统全部做完，使每张卡片最终可行

## 二、依赖 DAG

```
地基层（无依赖，先做——按主人顺序）：
  M5a 关系值系统 ────→ 四族关系（±1/±2/±3，好结局 ≥12）——被 ①④⑤⑦ 依赖
  M5b 夺梦系统 ──────→ 采梦/夺梦暗代价（梦珀/记忆 vs 伤生灵）——被 ④ 依赖
  M5c 意志漂移 ──────→ CEV 污染（献名字/忒修斯 B/奥丁祭）——被 ②⑤ 依赖
  M5d 灵魂生机 ──────→ 灵魂守恒/夺魂/归河 + 生机（复活/奥丁祭献根须）——被 ③② 依赖

中游层（依赖地基）：
  明选引擎（数据驱动卡片容器：触发/选项/后果/差分）——消费关系值/领悟值/夺梦/意志
  卡片内容：①⑤（可落地）→ ④（夺梦后）→ ②③⑥（意志/灵魂/遗迹后）→ ⑦（终局）

终点层（依赖全部）：
  终局状态机 + 归还序列 + 多周目——⑦四路径
```

## 三、实施顺序（主人拍板 2026-09-01）

| 步 | 系统 | 内容 | 解锁 |
|---|---|---|---|
| 1 | **关系值** | 四族关系状态（±浮动）+ 存档 + UI + 修正函数 | 卡片①④⑤⑦ 的地基 |
| 2 | **夺梦** | 采梦/夺梦动作（梦珀/记忆产出 vs 生灵代价：伤神/枯萎）+ 惊扰 | 卡片④ 菟丝子 |
| 3 | **意志漂移** | CEV 污染值 + 视觉化（人称漂移/心语渐变）+ 事件注入 | 卡片②⑤ 的暗线 |
| 4 | **灵魂生机** | 灵魂资源（守恒/夺魂/归河）+ 生机（树生命力/复活/献根须） | 卡片③② 的灵魂拷问 |
| 5 | **明选引擎 + 卡片** | 数据驱动卡片容器 + 七卡按依赖逐张落地 | 明选全开 |
| 6 | **终局 + 多周目** | 终局状态机/四结局/归还序列 | ⑦ |

> 注：与最初草案（M5=明选基石）的差异——主人决定先补依赖系统、明选引擎与卡片后置；关系值/夺梦/意志/灵魂 每步独立设计→计划→TDD 交付。

## 四、每步的依赖输入/输出

| 步 | 消费 | 产出 |
|---|---|---|
| 关系值 | GameState/races（M3）、insight（M4） | relation 状态 + 修正 API |
| 夺梦 | races 人口/状态、memory/faith | 夺梦动作 + 生灵代价状态 |
| 意志漂移 | 明选/事件（后置）、GameState | drift 值 + 视觉化标记 |
| 灵魂生机 | 无（新资源） | soul/生命值 + 守恒机制 |
| 明选引擎 | 全部地基 | 卡片容器 + 触发/后果/差分 |
| 终局 | 全部 | 四结局判定 |

## 五、完成标准

依赖全部做完后，七张卡片无「依赖缺失」项；每张卡片落地时只需内容（文本/数值），不再需要新系统。
