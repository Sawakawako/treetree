# 世界树 M8：主玩法界面视觉与信息架构重构设计

> 日期：2026-09-06
> 状态：设计冻结，待实施计划
> 上游：M7 正式标题、双层持久化与记忆图书馆
> 权威约束：只重构 UI/UX 与展示层结构，不改变经营数值、解锁条件、存档格式或结局语义

## 一、背景与目标

当前主玩法场景把全部系统堆在一个 `ScrollContainer/VBox` 中：上百个控件共用一条纵向长页，`main.gd` 同时承担导航、展示计算、按钮接线、叙事反馈和终局覆盖层。它能够承载完整玩法，但在 420×640 竖屏中存在三个问题：

1. 首屏无法稳定表达“树正处于什么阶段、此刻该做什么、下一步会醒来什么”。
2. 基础成长、四族、树语、九界与终局入口互相挤压，后期只能依赖长距离滚动寻找操作。
3. 深灰原型样式与 M7 标题、图书馆已经建立的暖纸视觉语言割裂。

M8 将主玩法场景重构为触屏竖屏优先的渐进式界面：顶部固定资源摘要，中部一次只呈现一个领域页面，底部页签随当前周目进度出现，事件按重要度进入轻提示、叙事卡或阻塞式覆盖层。

目标是让玩家在任意阶段进入主场景后，都能在首屏看见当前阶段、心语、关键行动与最近目标；同时保留当前版本所有玩法入口和领域逻辑。

## 二、范围与非目标

### 2.1 本阶段范围

- 把 `features/ui/main.tscn` 改为固定主壳，保留原场景路径。
- 新增顶部资源栏、中部页面栈、底部导航和全局事件层。
- 把现有入口完整迁移到“树心、众生、树语、九界”四个独立页面。
- 页签按现有进度条件渐进出现；首次出现提供一次非阻塞提示。
- 建立普通轻提示、可展开叙事卡、阻塞式抉择/终局覆盖层三级反馈。
- 将 `main.gd` 中的展示计算和页面刷新职责拆到对应组件，保持单向数据流。
- 统一主玩法界面的主题、间距、触控尺寸、焦点态、滚动与对比度。
- 在早期、中期、后期、明选和终局状态做 420×640 运行时视觉验收。

### 2.2 非目标

- 不修改成本、产出、人口、关系、资源、离线收益或终局判定公式。
- 不增加、删除或合并玩法动作，不增加新的解锁门槛。
- 不修改 `GameState`、`save.json`、`meta.json` 或迁移规则。
- 不编写新剧情、世界观、故事、遗迹、结局或明选文本。
- 不重新设计 M7 标题场景与记忆图书馆。
- 不制作正式插画、位图、音效、音乐、设置页或发布包。

## 三、体验原则

1. **现在先于全貌**：首屏回答“现在是什么、现在能做什么、下一步是什么”，完整系统留在对应页面下方。
2. **渐进发现**：尚未进入玩家认知的领域不提前占据底部导航；现有条件首次满足后再出现。
3. **一页一意**：每个页面只承载一个领域，页面之间不互相嵌套控件或直接引用。
4. **叙事不淹没经营**：普通数值变化不弹层，值得停下阅读的内容才进入叙事卡，明选与终局才阻塞操作。
5. **暖纸承接年轮**：沿用标题与图书馆的白暖底、深棕字和暖金焦点，主玩法不再保留大面积深灰原型底。
6. **触屏优先而不排斥键鼠**：420×640 为基准，点击区至少 44px，同时维护清晰的键盘焦点顺序与鼠标悬停态。

## 四、总体架构

`features/ui/main.tscn` 保留为 `GameManager.MAIN_SCENE`，但根节点改为固定全屏 `Control`。主场景结构如下：

```text
MainShell
├─ Background
├─ SafeMargin
│  └─ MainVBox
│     ├─ HeaderRow
│     │  ├─ ReturnTitleButton
│     │  └─ ResourceBar
│     ├─ PageStack
│     │  ├─ TreeHeartPage
│     │  ├─ BeingsPage
│     │  ├─ LinguaPage
│     │  └─ NineRealmsPage
│     └─ BottomNavigation
└─ EventLayer
   ├─ ToastLayer
   ├─ NarrativeCard
   └─ BlockingOverlay
```

### 4.1 MainShell

主壳只负责：

- 进入主场景时调用既有运行态入口，并接收离线结算。
- 连接一次 `GameManager` 全局信号。
- 计算当前可见页签，切换唯一活动页面。
- 刷新顶部资源栏和当前页面。
- 把叙事与终局信号路由到 `EventLayer`。
- 切页时保留各页本轮会话内的滚动位置；重新进入主场景默认回到“树心”。
- 当前页面因新周目条件变化而隐藏时，安全回退到“树心”。

主壳不计算领域成本、不修改 `GameState`、不自行结算动作。

### 4.2 页面控制器

四个页面具有统一的 `refresh(state: GameState)` 展示契约。页面控制器：

- 只连接本页按钮；
- 只调用现有 `GameManager` 公共动作；
- 动作完成后只发出 `refresh_requested`，由主壳统一读取最新状态并刷新资源栏与当前页；
- 使用纯投影函数计算标签文本、可见性、禁用态和缺口提示；
- 不使用 `_process` 轮询，不直接写 `GameState`，不负责存档；
- 不连接或引用其他页面。

### 4.3 ResourceBar

资源栏默认稳定显示树液、生长、记忆、信仰四项摘要。当前页面依赖灵魂、领悟或希望时，在页面标题区显示对应的暖金上下文资源标记。点击资源栏可展开完整资源、容量和已有公共查询能够提供的产速，再次点击或切页时收起。某项若没有现成的公共产速查询则只显示存量与容量，UI 不自行复制产出公式。

资源数字变化以短促淡入/上移反馈呈现；只显示差值，不遮挡当前操作，也不进入事件队列。

### 4.4 BottomNavigation

底部导航固定在安全区内，可见页签平均分配宽度。页签顺序永久为：树心、众生、树语、九界。隐藏只影响当前显示，不改变相对顺序。

每个页签包含文字标签和选中态；本阶段不引入新的位图图标。首次出现使用一次暖金呼吸提示，结束后回到普通状态，不循环闪烁。

## 五、页面信息架构

### 5.1 树心页

首屏固定顺序：

1. 当前成长阶段与既有心语。
2. 下一目标：按固定顺序投影首个尚未完成且已有规则可计算的目标——当前新手教学步骤、下一项可见基础升级、下一次根须探索、下一项页签解锁；同类目标沿旧界面顺序选择。若上述目标均已完成，则显示既有终局入口的最近缺口。目标只引用 Manager/Actions/Catalog 已返回的条件，不创造新门槛。
3. 当前关键行动：始终突出树心页已有的 `GatherButton`（采集日光），不把其他页面的动作搬到首屏；当前页内新近可用的升级或探索只通过“下一目标”和对应卡片的暖金描边提示。
4. 基础资源摘要和当前增长反馈。

下方卡片承载：

- 舒展叶片、分枝、叶绿体、木质部、花盘、螺舱、根须等级；
- 根须探索与遗迹进度；
- 嫩叶教学链、深根梦、风语膜。

现有 `GatherButton`、七类基础升级、`RootExploreButton`、`SeedlingButton`、`DeepDreamButton`、`WindVeilButton` 均在本页保留。遗迹正文不常驻占位，改由事件层展示。

### 5.2 众生页

首屏展示四族摘要：是否苏醒、人口、关系与当前可用互动。未苏醒族群保留现有唤醒条件提示，但不展开空操作区。

下方按族群与主题组织：

- 四族仪式互动、亲密事件与夺梦；
- 火塘、歌之环、铸根坊、图腾柱设施；
- 复活与夺魂；
- 图腾、领悟、化身；
- 说书人主线与小溪彩蛋。

同一族的相关动作进入同一卡片，按钮仍逐一对应原动作，不合并结算。族群事件、图腾解读与故事正文进入叙事卡。

### 5.3 树语页

首屏展示生命之语、记忆之语等级和当前建议点亮的一个节点。下方承载：

- 树液到信仰、树液到记忆的转换；
- 信仰引擎与记忆引擎；
- 生命之语、记忆之语升级；
- 现有生命/记忆树语节点及其前置、成本和状态。

已点亮节点以完成态保留在节点路径中，不再从界面完全消失；不可点亮节点明确显示现有缺口。视觉变化不改变 `LinguaActions` 的判断结果。

### 5.4 九界页

首屏展示已获得回响数量、世界之语等级、当前路径提示和世界之轴缺口。下方承载：

- 冠、干、根三域九界；
- 世界之语节点；
- 五奇迹与四族目标选择；
- 世界之轴入口。

近路/三域全景、二三周目回响标记、奇迹次数和所有缺口文字继续使用既有投影规则。抵达世界、点亮世界之语和施展奇迹后的正文进入叙事卡；世界之轴明选进入阻塞层。

## 六、页签出现规则

页签出现只投影现有 `GameState`，不保存新的解锁字段：

| 页签 | 出现条件 | 依据 |
|---|---|---|
| 树心 | 始终出现 | 主玩法基础入口 |
| 众生 | `races` 中至少一个合法族群 `awakened == true` | 已有族群苏醒状态 |
| 树语 | `lingua_life_level > 0`，或信仰已达到现有生命之语首次可用条件 | 对齐现有 `LifeUpgradeButton` 出现时机 |
| 九界 | `relics_found` 包含遗迹 9 | 对齐现有 `NineRealmsPanel` 出现条件 |

首次出现提示只存在于当前主场景会话，不写入存档。重新进入主场景时，已经满足条件的页签直接显示，不重复播放解锁提示。新周目若某条件暂时不满足，相应页签隐藏；既有跨周目保留数据仍按当前 `GameState` 自然决定可见性。

树语页签隐藏不改变底层动作条件；如果边界存档已经满足记忆之语条件但尚未满足生命之语显示条件，主壳还必须把“任一树语动作当前可执行，或已经存在树语等级/节点/引擎进度”视为树语页出现条件，避免现有入口被隐藏。旧版场景中仅仅存在但仍不可执行的 `MemoryLinguaButton` 不计为解锁依据，因此全新 `GameState` 仍只显示树心。该判断由纯投影测试覆盖。

## 七、反馈与事件仲裁

### 7.1 三级反馈

1. **轻提示**：采集、购买、资源转换和普通数值变化。显示在资源栏或页面顶部，短时存在，不夺取焦点。
2. **叙事卡**：离线结算、遗迹、族群苏醒、关系事件、夺梦揭示、图腾、亲密事件、故事、世界抵达、世界之语与奇迹。卡片从底部展开，可滚动、关闭并恢复原页面焦点。
3. **阻塞覆盖层**：明选、归还序列和结局结算。覆盖中部页面与底部导航，禁止点击底层；动作完成后按现有生命周期继续。

### 7.2 优先级与队列

事件优先级从高到低为：

1. 结局与归还；
2. 明选；
3. 叙事卡；
4. 普通轻提示。

同一帧收到多个内容时，只显示一个最高优先级项目，其他项目按到达顺序排队。阻塞覆盖层存在时，叙事卡不在其下方弹出；轻提示可以更新资源值，但不播放遮挡动画。关闭当前内容后展示队列中的下一项。

载入含 `pending_ending` 的存档时，恢复终局覆盖层优先于离线总结与普通叙事。覆盖层必须把初始焦点放在唯一安全动作上，关闭后将焦点恢复到触发控件或当前页标题。

### 7.3 失败与降级

- `GameManager` 动作返回失败时不改变页面；使用既有缺口或失败文本更新当前卡片。
- 请求切换到不可见页签时回退树心，不产生错误存档。
- 事件缺少可选正文时显示其标题和已有结果，不生成新的叙事补文。
- 动画被中断、页面被切换或场景退出时立即结束对应 Tween，不留下遮罩或不可点击状态。

## 八、视觉与交互规范

### 8.1 色彩与容器

- 主背景：沿用 `#f5f0e6`。
- 正文：沿用 M7 深棕主题色。
- 强调：`#e6a23c`，仅用于焦点、关键行动、当前进度和首次解锁。
- 卡片：暖白底、1px 柔和土金边线、约 12px 圆角。
- 禁用态降低强调但保持正文可读；关系状态不得只用颜色表达。

### 8.2 排版与尺寸

- 页面标题：28—30px。
- 分区标题：20px。
- 正文与按钮：16—17px。
- 辅助信息：14px，不承载关键条件的唯一表达。
- 左右安全边距：16—20px；主要区块间距 12px。
- 所有可点击区域最小高度 44px。
- 顶部资源栏和底部导航固定；只有中部当前页面纵向滚动，不出现横向滚动。

### 8.3 动效与焦点

- 页切换使用约 160ms 淡入；不使用弹跳或持续循环动画。
- 页签首次出现只播放一次轻微暖金呼吸。
- 键盘焦点使用 M7 暖金描边；方向键/Tab 顺序遵循从顶部、页面内容到底部导航的视觉顺序。
- 弹层出现时焦点限制在弹层内；关闭后恢复到触发点。

正文与背景对比度不得低于 4.5。按钮状态同时通过文字、边框或禁用状态表达，不把颜色作为唯一线索。

## 九、数据流与代码边界

数据流保持单向：

```text
GameManager / GameState
    ↓ 信号与只读查询
MainShell
    ├─ ResourceBar.refresh(state)
    ├─ ActivePage.refresh(state)
    ├─ BottomNavigation.refresh(visible_tabs)
    └─ EventLayer.enqueue(event)

Page button
    ↓
现有 GameManager 公共动作
    ↓
既有结果信号 / resources_changed
```

展示层允许新增纯函数或 `RefCounted` 投影对象，但不得复制领域结算逻辑。成本、能否购买、能否探索、能否互动、结局判定仍由现有 Manager/Actions/Catalog 提供；UI 只把返回值转换为可读视图。

建议文件边界：

```text
features/ui/
├─ main.tscn / main.gd                 # MainShell
├─ components/
│  ├─ resource_bar.tscn / .gd
│  ├─ bottom_navigation.tscn / .gd
│  └─ action_card.tscn / .gd           # 仅共享视觉与布局，不含领域逻辑
├─ pages/
│  ├─ tree_heart_page.tscn / .gd
│  ├─ beings_page.tscn / .gd
│  ├─ lingua_page.tscn / .gd
│  └─ nine_realms_page.tscn / .gd
├─ events/
│  ├─ event_layer.tscn / .gd
│  └─ ui_event_queue.gd                # 纯事件优先级与队列
└─ world_tree_theme.tres
```

页面脚本可保留与旧测试相关的纯静态视图函数，或把它们迁移到对应页面后同步更新调用方。不得为了复用而创建持有全部领域规则的“万能 UI Manager”。

## 十、迁移策略

1. 先用现有场景和状态快照补齐行为特征测试，列出所有旧入口与显示条件。
2. 建立主题组件、资源栏、导航和空主壳；此时不删除旧主场景逻辑。
3. 依次迁移树心、众生、树语、九界，每完成一页就证明该页全部旧入口可达。
4. 建立三级事件层，把旧 `LogLabel`、`DreamPanel`、族群事件区、`ChoicePanel`、`ReturnPanel`、`EndingPanel` 分级迁移。
5. 接入主壳统一刷新和页签投影，验证新周目与待恢复终局。
6. 所有行为与视觉验收通过后，删除旧单页节点和已无调用的巨型刷新代码。

迁移过程中保持 `features/ui/main.tscn` 路径、`GameManager.MAIN_SCENE`、公共领域 API 和存档内容稳定。旧场景节点只有在对应新入口和回归测试都存在后才可删除。

## 十一、测试与验收

### 11.1 自动化测试

- **导航投影**：新档只有树心；任一族苏醒显示众生；任一现有树语入口可见/可执行时显示树语；遗迹 9 出现后显示九界；条件消失时当前页回退树心。
- **资源栏**：四项默认资源、完整展开视图、页面上下文资源、格式化与差值反馈。
- **页面投影**：早期、中期、后期与跨周目状态下，旧按钮的可见、禁用、成本和缺口信息与现有领域判断一致。
- **入口清单**：原主场景所有动作节点都能映射到一个新页面或事件层，没有遗漏和重复结算入口。
- **事件队列**：优先级、同级 FIFO、阻塞层互斥、恢复焦点、`pending_ending` 优先恢复。
- **场景结构**：主壳、四页、资源栏、导航、三级事件节点完整，页脚与页面滚动互不嵌套。
- **无副作用**：纯刷新不改变 `GameState`，切页不保存、不推进 tick、不重复连接信号。

### 11.2 行为回归

完整验证以下现有流程：

- 新档采集与基础升级；
- 遗迹探索与四族依次苏醒；
- 关系、夺梦、亲密、图腾、灵魂与说书人；
- 树语升级、转换、引擎与节点；
- 九界、世界之语、奇迹与目标选择；

## 十三、风险与护栏

| 风险 | 护栏 |
|---|---|
| 拆页时漏掉旧按钮或显示条件 | 先建立旧入口清单与特征测试，每页迁移后做一一映射 |
| 多页面重复连接 `GameManager` 信号 | 全局信号只由 MainShell 连接；页面只接本页按钮 |
| 事件同时到达造成弹层重叠 | 单一 EventLayer + 可测试的优先级队列 |
| 隐藏页签让边界存档失去入口 | “任一现有入口可见或可执行”兜底投影，并覆盖损坏/旧档状态 |
| 固定头尾压缩正文空间 | 中部独立滚动、44px 控件、420×640 多阶段截图验收 |
| 为了 UI 便利复制领域逻辑 | 所有判断继续调用现有 Manager/Actions/Catalog，投影只组织返回值 |
| 大爆炸替换难以定位回归 | 主壳与四页分阶段迁移，旧节点只在替代入口验证后删除 |
