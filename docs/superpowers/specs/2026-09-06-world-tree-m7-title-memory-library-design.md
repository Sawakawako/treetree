# 世界树 M7：终局外壳与记忆图书馆设计

> 日期：2026-09-06  
> 状态：设计冻结，可实施  
> 上游：M6 真结局循环终止、M6-D 九界与奇迹  
> 权威约束：真结局回标题，不开放自由增量模式；图书馆只供重读

## 一、目标体验

玩家第一次启动时，看见一粒尚未发芽的种子。走过的遗迹、听过的故事与抵达过的世界，会在标题页后留下书页。真结局清除当前周目，却不再清除这些书页。

本阶段完成三个闭环：

1. 启动游戏先进入正式标题场景；有当前周目时可继续，没有时从一粒种子开始。
2. `save.json` 只保存当前周目；`meta.json` 独立保存跨存档见闻。
3. 记忆图书馆可重读遗迹、图腾、说书人故事、明选、九界、奇迹和已见结局；真结局后完整解锁当前版本的全部馆藏。

## 二、范围与非目标

### 本阶段范围

- 标题场景：继续、新的一轮、记忆图书馆。
- 从主场景安全返回标题；返回前保存当前周目与元进度。
- 新开一轮前二次确认，避免误删当前周目。
- 真结局“回到标题”：归档见闻，标记图书馆完整，删除当前周目，保留元进度。
- 图书馆七类馆藏、锁定态、分类计数、正文重读和返回标题。
- 旧存档迁移：第一次启动新版时，把旧 `save.json` 中已有见闻并入 `meta.json`。

### 非目标

- 不做真结局后的自由经营模式。
- 不做多存档槽、云存档、设置页、制作人员页。
- 不补写设计中尚未实现的 20 个遗迹、12—15 个故事或 30 个彩蛋；完整解锁仅覆盖当前版本已有数据。
- 不制作高成本标题插画。本阶段先用项目既有白暖色与排版完成可玩的正式外壳。

## 三、数据所有权

| 数据 | 所有者 | 存储 | 清除规则 |
|---|---|---|---|
| 当前资源、等级、关系、人口、周目结算 | `GameState` | `user://save.json` | 新开一轮或真结局后清除 |
| 已见遗迹/图腾/故事/明选/九界/奇迹/结局 | `MemoryArchiveState` | `user://meta.json` | 普通游戏流程不清除 |
| 图书馆完整解锁 | `MemoryArchiveState.library_complete` | `user://meta.json` | 真结局达成后永久为真 |
| 场景切换与保存时机 | `GameManager` | 不另存 | 标题、主场景只发出请求 |

`MemoryArchiveState` 是纯 `RefCounted` 数据对象，不成为第二个 Autoload。`GameManager` 负责生命周期，`SaveManager` / `MetaSaveManager` 只负责版本化 JSON 读写。UI 只读取目录投影，不直接修改存档对象。

## 四、归档规则

### 4.1 自动并集

每次自动保存、返回标题与终局结算时，把当前 `GameState` 的见闻并入元进度：

- `relics_found` → 遗迹
- `totem_interpreted` → 图腾
- `storyteller_stories` → 说书人故事
- `choices_done` → 明选卡
- `realm_echoes` → 九界
- `miracle_counts` 中次数大于 0 的 id → 奇迹
- `ending_seen` → 结局
- `run_number` → 抵达过的最高周目

集合只增不减并按资料库顺序展示。损坏或未知 id 在读档时丢弃，避免未来内容改名后污染 UI。

### 4.2 真结局完整解锁

真结局结算后立即设置 `library_complete = true`。图书馆据此显示当前构建中全部馆藏；以后追加合法资料时也会自动可读，不必改写旧 `meta.json`。

完整解锁是叙事奖励，不返还资源、不重开经营、不改变结局判定。

### 4.3 明选边界

图书馆重读明选的题面与选项，不重演选择、不再次结算后果。元进度记录曾选过的选项 id，用于标注“年轮里留下的路”；旧档无法还原的选项保持不标注。

## 五、场景流

```text
启动
  → 标题
      ├─ 继续这一程（存在 save.json） → 主场景
      ├─ 新的一轮 → 二次确认 → 新 GameState → 主场景
      └─ 记忆图书馆 → 分类/条目/正文 → 返回标题

主场景
  → 回到根外 → 保存当前周目 + 归档 → 标题

真结局
  → 回到标题 → 完整归档 + 删除 save.json → 标题
```

标题场景挂载期间，`GameManager` 停止经营 tick，防止已经清除的真结局存档在后台重新生成。

## 六、界面结构

### 6.1 标题

- 顶部：`世界树`。
- 心语：`风从旧土上经过。\n有些名字，还在叶脉里。`
- 主按钮：继续这一程 / 新的一轮 / 记忆图书馆。
- 状态行：当前周目是否存在、馆藏已解锁数。
- 新开确认层：明确提示只清当前周目，图书馆仍会保留。

### 6.2 记忆图书馆

420×640 竖屏单列布局：标题 → 分类选择 → 完整度 → 条目列表 → 正文阅读区 → 返回。列表与正文各自滚动；锁定条目显示 `尚未落进年轮`，不可打开。

七类顺序固定：遗迹、图腾、说书人、明选、九界、奇迹、结局。正文直接读取现有资料库，不复制第二套文案。

## 七、存档兼容与失败策略

- 两个 JSON 顶层都写 `version`。
- 缺字段走默认值；非法类型与未知 id 过滤。
- 写入使用临时文件并保留 `.bak`，成功解析后再替换主文件。
- `meta.json` 损坏时先尝试 `.bak`；仍失败则从当前 `save.json` 可见内容重建。
- 删除当前周目只允许精确目标 `user://save.json`；不得删除整个用户目录。

## 八、验收标准

1. 首次启动没有存档时，“继续这一程”不可用，新的一轮可进入主场景。
2. 有存档时可继续；主场景返回标题后，资源与进度仍在。
3. 新的一轮需确认，确认后当前周目重置，既有图书馆条目保留。
4. 普通流程只显示真正见过的条目；锁定内容不泄露正文。
5. 真结局后 `save.json` 不存在，`meta.json` 存在且图书馆全部可读。
6. 旧 M6-D 存档升级后，已有遗迹、故事、九界、奇迹与结局能进入图书馆。
7. 420×640 下标题和图书馆无横向溢出，正文可滚动，按钮可点击。
8. 全量 GdUnit4、主场景和标题/图书馆冒烟均通过，无错误与孤儿节点。
